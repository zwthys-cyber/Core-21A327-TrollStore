# 实时人物数据采集版

此包用于取得当前组件的完整骨骼变换数组、组件变换、原投影结果，以及现有几何查询的命中距离。它不是完整人物填色完成版。实际手机上的读取成功、姿态与当前衣服的绑定、遮挡查询可用性仍由新报告验证。

基于已发布 Core v19，保留其 600 米显示和初始化路径。可选构建命令为 `python3 scripts/build.py --model-capture`，只在 GitHub Actions 执行。普通构建不启用采集；采集版的 bundle build 为 21，`CoreModelCaptureVersion=1`。

已发布 [model-runtime-capture-v1](https://github.com/zwthys-cyber/Core-21A327-TrollStore/releases/tag/model-runtime-capture-v1)，预发布且不替换正式最新版 v19。IPA 7,208,679 字节，SHA-256 为 `aecfeabb46fe6ce8014033cc97cb485f7682dafb7ae144787c373f447a6ac93c`。发布的五个附件、四项校验及根目录 IPA 已核对一致。

[云端检查和设备构建 38556662721](https://github.com/zwthys-cyber/Core-21A327-TrollStore/actions/runs/38556662721) 全部通过，源码和发布标签指向 `db6341c8208f189c72afe4079cf226f00991350e`。检查覆盖 37 项原回归及可选导入改动、原生清零/errno 转发、递归读取隔离、完整数组采样、间隔/限额、帧布局与非法步长拒绝、射线锁/命中/未命中/损坏/预算、变换计算和本地报告。设备签名、依赖、导入和精确字节核验通过。此为云端验证，实机采集尚未得到报告确认。[普通 Core 构建 38555937751](https://github.com/zwthys-cyber/Core-21A327-TrollStore/actions/runs/38555937751) 也通过。

## 手机操作

1. 用 TrollStore 覆盖安装 `Core-17.0-21A327-TrollStore-model-capture-v1.ipa`。
2. 打开 Core，正常初始化内核、获取信息和开启悬浮菜单。
3. 进入游戏并让附近人物出现在画面中，移动视角观察数秒。采集窗口从 Core 启动后开始，约三分钟；若初始化耗时超过窗口，重新打开 Core 后再进入游戏。
4. 从“文件 → 我的 iPhone → Core”取出 `Core-model-runtime-report.json`，放到 `/root/core`。报告也会在没有成功样本时写入观察次数和跳过原因；无需再次导出静态资源包。

## 读取与报告边界

只在可选版本中，将 Core 原 `_bzero` 导入映射到相同 ABI 的转发函数；原代码、导入 stub、系统调用和返回地址不移动。转发保持清零参数、结果及 errno。ARM64 入口用尾跳转携带调用者帧指针和远程地址寄存器，正常调用在转发后不触发采集。

采集仅接受原 Core UUID、读取器 `E1908` 的首次清零调用、原骨骼采集器 `D897C` 调用后返回位置 `D8980`、44 字节组件变换目的缓冲，以及经过边界检查的帧布局。数组指针、数量来自原采集器刚读到的结构；步长从原配置取得。最多读取 256 个、44/48 字节步长的变换，完整保存所定位组件声明的数组，不能据此证明已包含人物所有附件组件或衣服形变。

每个组件最多两个样本，相隔至少两秒，最多三个组件、六个样本。变换读取在原采集线程完成；数据复制后交给独立串行队列写报告，避免异步访问失效的栈和变换缓冲。报告写入应用自己的 Documents，最多 2 MiB，不发送网络请求。

另对已经定位的同一骨骼组件读取一次不超过 2 KiB 的布局样本，用于后续识别其网格引用字段；不沿未知指针遍历对象。该样本以 Base64 写入本地报告，读取失败不影响已取得的姿态。报告明确标记该布局尚未经过类型解释，不能据此宣称已定位实际渲染网格。

世界位置由组件变换和组件空间的骨骼平移计算，二维位置通过原 Core 投影函数取得。报告没有引擎帧编号，不宣称多个远程读取组成了原子的同一引擎帧快照。

遮挡样本使用原几何场景的同一锁及射线查询入口。只有几何就绪、三个场景均存在时查询，记录相机至关节点的命中/未命中和原世界单位的距离。逐次查询之间检查约 10 ms 的预算，达到预算后保留未知值及截断标记；该预算不能中断已经进行的原锁或射线调用。它不是游戏 GPU 的逐像素深度纹理，也不是身体填色已经完成的证明。

## 静态分析依据

- 原 `D897C` 通过 `E1908` 读取 44 字节组件变换，数组指针在调用者 `SP+0x110`、数量在 `SP+0x118`。
- 原 `E1908` 的帧指针为其入口 SP 减 16，原保存的组件指针在 `FP-0x48`、采集上下文在 `FP-8`。`E195C` 调用清零后返回 `E1960`；所有检查均先于额外读取。
- 原骨骼批量读路径 `D8DAC..D8DD0` 检查配置步长 48，并读到最后所需骨骼的 44 字节有效部分。本采集版保存完整声明数量，不改原骨骼选择或绘制。
- `D33F4` 使用 `BD4F78` 的共享锁访问三个本地几何场景。`E0BE8/E0CF0` 的返回缓冲为 80 字节，距离在偏移 32，几何 ID 在偏移 72。原判定用几何 ID 是否为 `UINT32_MAX` 区分命中。

当前仍未确认运行时组件与静态衣服网格的对应关系，完整顶点/索引/蒙皮权重解码及像素级轮廓渲染也未完成。实机数据采集是继续核对这些连接的输入。
