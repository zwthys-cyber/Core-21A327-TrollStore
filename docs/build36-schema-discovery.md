## 确认的代码缺口与 build 37

两类组件扫描分别有 341/338 个字段、695/690 次头部读取、各 6 次读取失败，并标记截断。当前 LOD 仍未取得。旧代码与部件读取共用截止时间，一次扫描中途失败的结果仍会永久缓存；每类 192 字段上限还可能截断优先引擎类的后续定义。这些是代码缺口，不能从本轮报告断言 LOD getter 必然位于被截断部分。

build 37 / render v9 将扫描改成保留游标的分帧步骤：每帧全局最多一个 16 节点步骤，使用独立 2 ms 远程读取窗口。保留 SceneComponent / SkinnedMeshComponent 的优先级、总计 384 字段和 896 次头部读取限制；去掉单类 192 字段提前截止，缓存已校验的属性类头，避免逐字段重复读取。每个类最多三轮扫描，读取失败后等待一秒再试；重试时保留已确认字段，永久故障不会每帧重扫。部件原有剩余读取预算在步骤后恢复，不因扫描而重新获得完整 12 ms。

状态报告新增扫描是否结束、步骤数、每类字段数、头部/名称读取及各上限信息。另分别统计开关关闭、几何未就绪、相机不可用和目标列表读取失败造成的绘制入口退出，便于区分后续停止填充。包 build 号使用 37，避免与本次上传目录混淆；采集协议仍为 7。

新增合成场景验证 192 个字段之后的严格类型化 LOD getter 可以分步发现、属性类头不逐字段重复读取、每步节点和读取上限、临时故障重试、每帧一步及退避、最多三轮停止、已确认字段和剩余数据读取预算保留。自动化测试及编译只在 GitHub Actions 执行。

本改动不能直接确认该定制游戏的实际 LOD。精确材质透明裁剪、服装形变、相机/姿态帧同步和最终墙沿 GPU 深度仍未验证，`full_requested_effect_verified` 保持 false。
