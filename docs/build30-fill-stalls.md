## build 31 改动

1. 恢复按场景批量查询，沿用已修正的 96 字节、16 字节对齐结果。每场景每帧的首个待定像素仍与原包装函数比较，不一致即禁用批量并回退。独立测试继续写满第 80–95 字节，覆盖 build 29 的越界根因。
2. 每秒轻量核对对象完整身份、附件数组、绑定资源和 GPU 流/索引/分区描述；未变化时复用名称、参考骨骼和静态网格。改变或未知时才走全量刷新。当前姿态、变换、可见性和 LOD 每帧重读。
3. 当本帧已用掉一次元数据检查机会时，其他仍有效的缓存目标继续按实时状态绘制。已知身份变化或刷新失败的模型仍拒绝绘制。刷新结果暂存后整体提交，失败不覆盖旧的有效数据；载入中及活动目标的缓存引用继续受保护。
4. 每帧一次读取原生人物列表，按 16 KiB 分块，结束时重查 vector 起止地址，替代每个目标逐个记录调用本进程 VM 读取。
5. 全分辨率像素由 20 字节缩至 8 字节，仅保存透视逆深度和分类；像素中心射线恢复表面坐标。没有降低采样率或复用上一帧颜色。
6. 将相邻行中位置、宽度、颜色完全相同的条带合成矩形。每个覆盖像素保持相同颜色，空行和颜色变化中断合并，不扩大人物轮廓。4096 上限改为矩形数量，避免高人物/长色块仅因逐行计数而整帧消失。
7. 报告新增有效入口、投影部件、轻量检查/复用/延期、元数据耗时、人物列表读取块数、像素内存、查询未完成和矩形超限计数。旧 `filled_spans` 在此版本与 `filled_rectangles` 都表示提交矩形数，不能与旧版逐行条带数直接比较。
