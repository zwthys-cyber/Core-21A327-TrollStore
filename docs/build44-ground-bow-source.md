# v16 / build 44：弓弩近距漏显排查

用户实机反馈：v15 的地面弓弩只有不到约 20 米时出现；靠近显示后退到 30～50 米，标记又消失。本版增加能够区分源列表、采集缓存和投影的记录，**尚不宣称修复距离问题**。原 v15 的主程序显示补丁保持一致：地面白名单仍只有爆炸猎弓／十字弩，保留手持名称、车辆和全精度填色。

## 已知证据

- [Actions 39431614153](https://github.com/zwthys-cyber/Core-21A327-TrollStore/actions/runs/39431614153) 对固定输入及 v15 全部静态补丁作只读核查，覆盖上游识别、原物品采集、位置读取及绘制路径。本机只编辑与阅读文本，未执行二进制分析。
- v15 原物品采集 `D9954` 跳到固定有限值 0～600 米检查 `D9E3C`，通过后沿用原缓存追加；绘制在 `DDF7C` 再检查 600 米。未发现正在限制这两种普通地面弓弩的直接 20 米距离分支。
- `DE394` 的 20.0 用于文本坐标的缩放偏移，不是距离比较；`D9AA0` 的 30.0 属于已被普通地面物品路径绕过的另一类记录，不能见到数字就改写。上游 479.5±0.1 的浮点识别条件也不是米制距离比较。
- 此前完整 ARM64 回归验证了“源列表中已有有效弓弩记录”时，600 米内可采集和绘制；位置读取等使用合成有效数据，不能据此承诺实机有全部 600 米目标。接近后退远即消失的反馈仍需实机阶段记录，不能直接认定为游戏加载、服务器同步或某个已知配置限制。

## 新记录与边界

每秒在原后台报告队列安全复制 Core 现有本地物品源列表（32 字节记录）和显示缓存（88 字节记录），按精确原生弓弩名称分别统计。记录每种弓弩的源／缓存计数、20 米内／20～600 米缓存数、最大当前缓存距离、原生投影标志和开关状态。

只跟踪已识别过的弓弩指针，以进程内序号保留最多 32 条阶段变化，最多跟踪 256 个对象。退出缓存后当前距离为 null，最后缓存距离附年龄；它不用于绘制。指针复用不等于游戏身份验证。不可读或超限的名称明确标为 unknown，不能据此判断不存在弓弩。

每次最多 8,192 条源／缓存记录、256 个元数据对象、2 MiB 本地复制请求；向量头变化、已知原采集回调重叠、读取失败、格式超界和旧原采集状态均不会当作目标正常消失。上述条件不是游戏数据的原子快照。诊断不调用额外游戏内存读取，不修改游戏数据、主程序采集／绘制分支或旧目标屏幕位置。

独立报告 `Core-ground-bow-status.json` 每五秒写入原报告目录，避免弓弩历史挤占原人物报告的大小上限。`Core-model-render-status.json` 中另有 `ground_bow_trace` 汇总和报告文件名，`render_version=16`。未完整取到列表时保留上一有效报告，并显示失败次数和样本年龄。

## 实机复现

覆盖安装后完全退出 Core 并重新打开。开启“弓弩位置”，在同一把地面武器旁等待至少五秒，再退到 30～50 米、保持朝向武器且等待至少五秒。保存并提供 `Core-ground-bow-status.json`，其阶段历史可用于判断是源列表缺席、源中有而缓存无，还是缓存仍有但投影失效。保留两种武器白名单，不需要开启其他物资。

所有编译和回归只在 Actions 执行。新增原生测试覆盖短／长字符串、20／30／50／600 米分组、缓存与源分别消失、投影单独变化、未知元数据、采集重叠拒绝、复制／记录／历史上限及关闭填色时零额外游戏读取／绘制。原 58 项 Python、原生模型／全精度参考栅格／并行 TSan、7 项 Node、载荷／签名／入口检查继续执行。
