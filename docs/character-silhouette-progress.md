# 实际人物轮廓与精确红白分色

目标是与本帧实际身体、衣服、头发和姿态匹配的完整人物轮廓：露出部分白色，遮挡部分红色。没有把骨骼包络、固定服装模型或整段关节着色标为完成。

## 当前可用数据

采集 v2 已实机取得 3 个组件、6 个快照，每个保存 68 个有效变换；原几何查询已执行 1,224 次，全部未命中。21 份静态衣服、头发及附件样本已有 LOD0 顶点、索引、蒙皮权重和参考骨骼，但其中没有当前已验证的完整基础身体资源。衣服样本的参考骨骼数为 61/63/76/82，不能把 68 项运行时数组直接按编号套给它们。

原悬浮层具有二维多边形填充接口，但填充接口本身不提供实际人物轮廓。精确分色还需要与相机和姿态对应的深度/遮挡结果，透明裁剪与服装形变也影响人物边缘。

## v3：绑定证据与遮挡对照采集

当前源码构建采集协议 3，Core build 23。保留 v2 已验证的 ARM64 原 LR 传递和小栈转发，将单个组件布局扩大到 4 KiB。

只检查 v2 样本已经出现引用/数组形状的固定槽位。最多接受 12 个对象头形状候选，每个保存 1 KiB 前缀及一个 40 字节类头；候选数组最多保存前 4 项，单快照最多 40 次读取。拒绝越界、未对齐、无效头字段、异常数量/容量和读取失败，不递归扫描候选对象的其他指针。候选及其语义类型明确标记未验证，不把字段形状当作已经找到 SkeletalMesh。

姿态间隔改为至少 10 秒，仍为 3 个组件各 2 次、最多 6 个快照，供墙前/墙后对照。报告采用紧凑 JSON，保留 2 MiB 文件限额及本地保存方式。

手机测试需在 Core 打开后的 3 分钟内正常开启附近敌人，并在第二次采样前移动到墙体遮挡目标的视角。新报告 `capture_version` 应为 3；需要核对引用候选、实际网格身份、射线命中与同时观察到的场景变化。

## 尚未完成的必要条件

1. 确认本次组件及附件实际引用的网格资源，并核对基础身体资源、骨骼名字/层级与运行时数组的映射。
2. 确认材质透明裁剪、实际服装/头发形变和相机帧的一致性。
3. 取得并验证遮挡命中及精确深度/像素遮罩来源，才能接入最终三角形填充和逐像素红白判定。

目前没有可用的游戏 GPU 深度纹理或完整人物遮罩接口；本地几何射线的未命中样本不能替代上述条件。完成状态仍为未完成，v3 是取得必要输入的步骤。

编译和所有自动化验证只在 GitHub Actions 运行。原始游戏资源、组件布局及设备日志保留本地，仓库只记录汇总和代码。
