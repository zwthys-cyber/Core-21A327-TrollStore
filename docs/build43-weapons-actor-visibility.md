# v15 / build 43：两种地面武器、手持武器名称及人物漏显记录

用户明确要求：地面只保留爆炸猎弓、十字弩的位置和距离，其他地面武器／物资暂不加入；另外可以显示敌人手持武器名称。延续 v14 的附近载具、人物标记、独立全精度填色开关。

## 武器显示

- 新增独立、原偏好机制保存的“弓弩位置”（`+0x21`）和“手持武器”（`+0x24`）。原附近敌人、附近载具、人物填色开关继续独立。五个控件的 changed 返回均写原 dirty 标志，原 EndChild 只执行一次。
- 地面来源列表及绘制列表两处都只接纳十字弩／爆炸猎弓的精确原生名称；同时保留独立车辆路径，拒绝投掷物、弹药、战术弩、燃点复合弓、普通枪械等。无关物资在位置读取前拒绝；已缓存对象在绘制时再次检查类别和开关。距离及投影沿用已验证的原生有限值、0～600 米（包含边界）条件。黄色黑描边文字显示名称和距离。
- 固定原包的地面其他武器表只有迫击炮与爆炸弓两项，未包含十字弩的独立包装类。仅在此精简配置中，将不显示的迫击炮地面条目替换为 `BP_Other_CrossBow_Wrapper_C`，指向原包已有“十字弩”名称；原爆炸弓条目改用原包已有“爆炸猎弓”完整名称。保留原生类别、分类器、数据读取及所有手持武器映射。包装类拼写也与[原作者发布的物品类表](https://github.com/atiksoftware/pubg_mobile_memory_hacking_examples/blob/master/README.md)一致；该旧表不是当前游戏实机验证。
- 手持名称启用原人物绘制中的文本分支，绕过旧图标偏好，使用原武器名称查表、白色黑描边文字和 14 倍原界面缩放。保留人物队伍、距离和投影检查；未知武器仍受原映射能力限制。本次不增加手持武器的独立远程读取路径。
- 静态变更仅使用 Actions 审阅的不可达原面板空间和原只读文字；签名前修改，运行时不写可执行内存。输入处理入口继续禁用。

## 人物漏显诊断

用户补充：载具在 600 米内正常显示，人物在山后或远处有时整套姓名、方框、射线均消失，v19 也有此问题。车辆和人物是不同采集路径，不能用车辆覆盖范围证明人物数据已存在。代码中的绘制／骨骼条件为 600 米；已有分析未发现明确的 300 米距离跳过常量，仍不能确认是游戏同步限制或本程序采集错误。

新增后台一秒一次的只读对照，记录 Core 已有的人物源列表 `+0x3C0/+0x3C8` 和标记缓存 `+0x3F0/+0x3F8`。关闭填色也会记录，不读取额外游戏内存，不在方框绘制线程复制列表。已知原采集入口执行期间的样本由原子 generation／active 检查拒绝；向量头变化、超界、读取失败或旧缓存也不发布为“目标消失”。这些保护不构成游戏数据的原子快照。

报告写入原 `Core-model-render-status.json` 的 `actor_visibility_trace`：源候选数、仅源列表存在的候选数、缓存内 0～300／300～600 米等计数，以及最多 64 条阶段变化。最多跟踪 512 个目标，使用进程内序号，不导出目标地址／玩家姓名。缓存消失时当前距离为 null；保留的最后缓存距离附带年龄，不作为当前位置。原指针复用不能证明同一个游戏身份。样本缺席也不能证明游戏或服务器没有该人物。

## v14 最新报告的判断

21:15:38 UTC 的 v14 报告中，1,957 个有效准备入口包含没有形成遮罩的帧。完成填色 490 次、查询不完整 300 次，实际遮罩尝试约 790 次，查询不完整约 38%；不能用全部入口平均值宣称延迟大幅改善。绘制回调最大 111.189 ms，填色最大 77.95 ms。静态片段复用约 6.8 MB 已生效，但逐像素查询和采集尖峰尚存。与 v13 场景工作量不同，也不能直接作性能倍率比较。

本次未盲目并发调用原生几何查询、放宽 12 ms 查询时限、降低像素精度或复用上帧屏幕结果。人物漏显／跟随延迟均不宣称已修复，需结合新实机样本继续定位。
