## 代码中发现的问题

模型阶段的顶点和三角形循环反复读取 Objective-C 属性及 NSData 指针。旧循环每帧重新解码静态索引，并逐三角形调用 `NSMutableData appendBytes:`，之后栅格循环还逐三角形查询数组长度。这些重复工作没有改变本帧模型，却占用主线程。

另一个独立问题是远程读取限时：同一目标先读取并蒙皮第一个部件，再读取后续部件；12 ms 截止时间包含前面部件的 CPU 工作。即使远程读取本身正常，后面附件也可能尚未读取就被拒绝。这是由代码与合成场景定位的问题；build 32 缺少失败原因明细，尚不能将其确定为本次所有不可用记录的根因。

## build 33 改动

- 先采集本帧选中部件的状态、静态缓冲和当前姿态，再集中进行 CPU 蒙皮/投影。前面部件的 CPU 时间不再使后面部件的读取截止时间失效，仍保留原有界读取、对象身份和可见性/LOD 检查。
- 在网格载入时将通过范围校验的 16/32 位索引解码为缓存 uint32 数组，计入 24 MiB 缓存成本。本帧保持静态索引，栅格时根据当前顶点有效性跳过无法投影的三角形，保留原先的过滤行为。
- 每个网格循环前一次取出原始数据指针和标量数量，顶点/三角形循环不重复访问对象属性，不逐三角形追加 NSData。不改变骨骼权重、蒙皮数学、像素中心或红白判定。
- 将模型阶段细分为 gather 与 skinning，原 mesh 总计继续包含两者。增加静态索引解码计数与 17 类网格载入失败原因，包含 reference/layout/index、读预算、各缓冲读取、分区/骨骼表范围及逆绑定等。
