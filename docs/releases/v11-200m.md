# Core 1.6 · v11 · 骨骼采集修复测试版

适用于现有 iPhone16,2 / D84AP、iOS 17.0（21A327）和 TrollStore。版本为 1.6 / build 12 / patch 11，安装包为 `Core-17.0-21A327-TrollStore-v11-200m.ipa`。

## 修复

用户的 v10 截图已经显示方框、射线和距离，但红白骨骼不明显。更新的设备日志确认 patch 10 已运行，内核后端到达 `state=2 / ready=1`，SpringBoard 注册成功；这三份日志没有遮挡准备或骨骼采集状态，无法据此确定全部原因。

静态检查发现 v10 统一了绘制开关，却遗漏原骨骼采集函数的两类开关与距离限制。旧骨骼开关关闭时，采集器不会按完整 14 段模型取得关节，即使绘制端已开启。v11 修正这四个指令位置，使原采集器也使用“附近敌人”开关和固定 200 米范围；保留原骨骼读取、模型索引检查、变换和遮挡查询。

显示策略沿用 v10：200 米以内敌人显示细方框、射线和距离，三者为白色。遮挡数据可用时绘制红白骨骼：一段的两端都无遮挡时白色，任一端有阻挡时红色。关节点判断不能实现身体轮廓填色或同一骨骼线上的精确墙边分界。原遮挡数据或对象未就绪时仍跳过骨骼，不强行设置成功状态。

## 安装与诊断

用 TrollStore 覆盖安装主 IPA；准备工具可以沿用。完全退出 Core，准备当前启动缓存后按原流程初始化、获取信息和开启“附近敌人”。重启手机后需要重新准备缓存。

在 `Core-21A327-adaptation.log` 中确认 `patch=11`。新增 `markers sampled` 行每 5 秒只读采样本进程的标记开关、遮挡请求、原几何就绪状态、三个场景对象是否存在，以及原关节缓存有效/遮挡数量。状态变化时记录，无变化时约每分钟记录一次。不记录场景对象地址或人物位置，不联网，不改动这些状态。

`cached_valid_joints` 和 `cached_obstructed_joints` 是非原子采样的共享缓存数量，可能属于最后处理的目标，不能当成当前帧的绘制数量。`geometry_ready=0` 或缺少场景对象意味着红白判断尚无所需原始数据；这份日志用于继续区分采集问题和遮挡准备问题。先验证正式对局内、同一目标在墙前和墙后的变化。

## 核验范围

29 项 Python 检查包含 v10 漏采集问题的指令级复现，并检查修正后两类目标、旧开关关闭/开启、旧距离限制、200 米边界、NaN/无穷及原 14 段索引扫描。其余检查覆盖允许修改范围、原输入代码返回、共享开关、窗口配对、固定样式、红白线段循环、缓存及包身份。新增四个指令外，原采集函数其余代码及原几何初始化/查询仍保持原样。

这些测试使用合成配置和图形/几何桩；GitHub macOS 另外执行原方法发布并发、Mach 转发、缓存传输、子进程清理、编译及两个 IPA 的载荷和签名核验。构建成功不等于手机上的红白效果已经验证，v11 仍需设备确认。后续 launchd 初始化超时仍未解决。

自瞄、压枪及其余显示仍停用。没有新增反作弊绕过、隐藏或防封保证；此前游戏封禁原因未知。服务器授权期限和设备绑定没有改变。本地卡密、日志和 kernelcache 不作为发布附件。

发布资产的来源提交、构建地址和摘要以 `release-metadata.json`、`build-metadata.json` 和 `SHA256SUMS.txt` 为准。
