# Core 1.6 · v13 · 姓名与 300 米标记测试版

适用于现有 iPhone16,2 / D84AP、iOS 17.0（21A327）和 TrollStore。版本为 1.6 / build 14 / patch 13，主安装包为 `Core-17.0-21A327-TrollStore-v13-300m.ipa`。

## 显示变化

用户已确认 v12 可用，并要求显示对方名字、将范围扩大至 300 米。v13 的“附近敌人”开关统一控制名字、方框、射线、距离和红白骨骼。原距离筛选和骨骼采集/绘制限制均改为 300 米，包含边界；保留原敌我、距离有效性、屏幕坐标和模型检查。

名字为白色，居中放在方框上方。沿用原姓名查询、缓存和读取校验，保留原短/长字符串复制、空名字的“未知玩家”或“人机”提示以及释放流程。姓名原本与血条和队伍编号共用面板，v13 只执行姓名路径，跳过队伍编号格式化/绘制及所有血条绘制，再恢复后续方框、距离与骨骼需要的坐标和距离寄存器。

方框、射线和距离仍为白色；原 14 段骨骼按关节点遮挡结果着色，两端无阻挡为白色，任一端有阻挡为红色。保留 v12 已验证可用的原遮挡启动调用和“全局”模式，以及 v11 的完整骨骼采集修正。场景未就绪时仍跳过骨骼；没有身体填色或轮廓。

## 核验范围

新增 ARM64 姓名路径回归：覆盖两类目标、开关关闭/开启、英文、中文、长名字、空名字提示，执行原字符串选择、定位和清理指令，检查只产生姓名绘制、长字符串释放一次、原姓名对象不被改写，并恢复后续标记需要的坐标和距离。姓名查找结果、字符串构造和外部图形接口使用合成桩；不运行手机上的游戏。

范围检查覆盖 200 至 300 米、300 米边界、超限、负数、NaN 和无穷，并核验采集与原 14 段循环使用同一范围。其余检查继续覆盖菜单、唯一开关、旧设置隔离、输入停用、原遮挡初始化、就绪条件、红白结果及完整打包。

31 项 Python 回归通过。GitHub macOS 另执行方法发布并发、Mach 转发、缓存传输、子进程清理，以及最终 IPA 的载荷和签名核验，全部步骤成功。v13 名字与扩大后的范围仍待实机确认；后续 launchd 超时仍未解决。

## 安装与日志

用 TrollStore 覆盖安装主 IPA，完全退出后重新打开 Core。原准备工具可以继续使用；按原流程准备环境、初始化、获取信息后开启“附近敌人”。该开关关闭时五项标记都不显示。

诊断日志仍为 `Core-21A327-adaptation.log`、`Core-remote-bootstrap.log` 和 `core-offline-original-id.log`，新检查点为 `patch=13`。遮挡状态采样继续只读本进程，不记录姓名、人物位置或场景地址。
