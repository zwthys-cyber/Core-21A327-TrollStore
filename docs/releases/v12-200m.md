# Core 1.6 · v12 · 遮挡启动修复测试版

适用于现有 iPhone16,2 / D84AP、iOS 17.0（21A327）和 TrollStore。版本为 1.6 / build 13 / patch 12，安装包为 `Core-17.0-21A327-TrollStore-v12-200m.ipa`。

## 问题与修改

v11 设备日志已确认新版本运行，但两次标记采样都是 `visibility_request=1 geometry_ready=0 scenes=0/0/0`。这说明遮挡引擎未就绪，红白骨骼被就绪检查跳过；缓存关节数量为零不能单独证明采集器还有错误。白色方框、射线和距离不使用这项遮挡结果。

静态检查发现，原“掩体判断”控件除了设置请求和模式，还在目标已绑定时调用原启动函数。此前精简了这组控件，只同步请求值，遗漏了启动调用和模式选择。

v12 在“附近敌人”开启且原目标已绑定后，选择原“全局”遮挡模式，并在开关由关闭变开启、模式变化或原启动标志未设置时调用原启动函数。原启动函数随后执行原初始化：核验后端快照、目标上下文和原场景来源，再创建场景并启动原线程。失败后仍保持未就绪，不伪造场景、关节有效性或遮挡结果，也不每帧反复启动。关闭后再开启标记可以再次请求原初始化。

只在已停用且不可正常落入的候选处理块内放置静态调用桥，保留原渲染函数栈、指针认证、收尾和全部原几何例程。主包继续保留 v11 的采集修正、200 米范围、统一开关和红白线段；两端均无阻挡为白色，任一端有阻挡为红色。方框、射线和距离仍固定白色。没有身体填色或轮廓。

## 日志核验

`Core-21A327-adaptation.log` 应出现 `patch=12 markers sampled`。在原采样之外新增以下状态：

- `target_bound`：原目标绑定字段是否非零。
- `visibility_mode`：原遮挡模式，1 为“全局”。
- `visibility_armed`：原启动函数设置的标志。
- `geometry_running`：原几何运行标志。
- `source_offset_available`：原场景来源偏移的两个编码值是否不同，与原初始化的零偏移检查对应；不代表游戏适配完整或地址一定可读。

诊断每 5 秒只读采样本进程，状态变化时记录，无变化时约每分钟记录。它不是原子快照，关节数量只是最后缓存的抽样，不是画面或目标计数。不记录来源数值、场景地址或人物位置，不联网。

原初始化若仍失败，需结合上述字段判断具体门槛；启动遗漏的修复不能证明当前游戏数据结构全部兼容。现有日志的后续 launchd 超时仍未解决。

## 验证范围

新增 ARM64 回归执行原启动函数及原初始化失败路径，组合检查开关、目标绑定、原模式和启动标志：只有满足条件才调用，调用后不会每帧重复，后端快照失败时保持场景为空、未就绪，并保留调用方栈和被调用者保存寄存器。既有回归继续检查原骨骼采集、菜单、旧设置、范围、就绪条件、14 段骨骼和红白结果。

macOS 构建另外执行方法发布并发、Mach 转发、缓存传输、子进程清理及最终 IPA 的载荷和签名核验。这些检查不运行手机上的游戏；实机红白效果仍待确认。

## 安装

用 TrollStore 覆盖安装主 IPA，完全关闭后重新打开 Core。已有准备工具可以继续使用。按原流程完成环境准备、内核初始化和获取信息，在位置页开启“附近敌人”。开启后等待场景就绪；若仍没有红白骨骼，导出新的三个 Core 日志以检查 v12 状态。
