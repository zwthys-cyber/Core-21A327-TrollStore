# Core 1.6 · v16 · 人数和身份标注测试版

适用于现有 iPhone16,2 / D84AP、iOS 17.0（21A327）和 TrollStore。版本为 1.6 / build 17 / patch 16，主安装包为 `Core-17.0-21A327-TrollStore-v16-300m.ipa`。

## 显示变化

屏幕顶部中央显示一个红色数字，表示原采集队列中通过敌我、有限距离及 300 米边界检查的敌人总数，合并真人和人机。原计数在屏幕投影之前更新，因此包含侧面和背后的目标；不要求名字、骨骼或方向箭头已成功画出。每帧原清零和累加流程保留，空列表显示 0。数字使用原黑色描边，字号为 24 个绘制单位乘当前缩放，顶部位置为 64 个绘制单位乘缩放。

分类直接追加在名字后，例如 `张三【真人】`、`名字【人机】`。使用原人机标志判断，不依据名字猜测。沿用原姓名查询、缓存及空名字提示；只对用于本帧显示的字符串副本调用原 C++ append，再按原流程测量宽度、居中绘制和清理。原姓名对象不改写。

“附近敌人”统一控制顶部总数、名字与分类标签，以及原正面标记和屏幕外提示。姓名仍为白色描边文字；总数为红色描边数字。身份在各自名字旁显示。

## 实现范围

顶部数字替换原独立真人/人机计数显示区域，读取原每帧计数器，不修改计数器写入、敌我判断、距离筛选、目标采集或投影。相加使用宽寄存器并限制到无符号 32 位范围，使用原 `%u` 文本及格式化、居中描边接口。无效缩放、尺寸、空间不足或格式化失败时跳过显示，随后执行原容器清理。

标签桥接放在仍禁用的雷达区域。人机标签复用原 `【人机】` 字符串；真人标签存放在已移除面板的旧“显示骨骼”文字位置，同为 12 个 UTF-8 字节。原 append 管理短/长字符串增长，原释放流程清理副本。雷达、旧面板、血条和队伍编号继续禁用。

## 核验

姓名回归扩展了两类身份、开关、英文/中文、长/空名字和 22/23 字节短长边界。检查标签 UTF-8 参数、只追加一次、原缓存不变、最终堆字符串按原代码清理，以及后续坐标恢复。

新计数检查执行原每帧清零和筛选累加，覆盖真人/人机、屏幕内/外、队友、300 米边界、超限、负数、NaN 和无穷，并验证下一帧没有目标时不保留旧数量。新数字绘制检查执行原居中描边包装器，覆盖 0、单类、混合总数、最大值、不同缩放和尺寸、开关、无效数据及格式化失败，检查红色、位置、字号和计数器只读。

本机和 GitHub 完整 34 项 Python 回归通过，适配库及日志检查通过 iOS SDK 编译。GitHub macOS 并发启动、真实 Mach 转发、日志轮换、缓存传输、子进程清理及最终包核验全部成功，下载产物再次通过载荷和签名检查。v16 实机数字及标签效果仍待确认；测试使用合成采集和外部图形/字符串桩，不运行手机上的游戏。原后续 launchd 接收超时仍未解决。

## 安装与日志

用 TrollStore 覆盖安装主 IPA，完全退出 Core 后重新打开。现有“Core 环境准备”可以继续使用；沿用准备、初始化和获取信息流程，再开启“附近敌人”。

日志检查点为 `patch=16`，profile 为 `enemy-markers-300m-count-tags`。原诊断和远程日志轮换继续使用，不记录姓名、身份明细或人物坐标。
