# Core 1.6 · v10 · 200 米标记测试版

适用于提供的 iPhone16,2 / D84AP、iOS 17.0（21A327），版本为 1.6 / build 11 / patch 10，功能配置为 `enemy-markers-200m`。在 v9 距离文字基础上，增加细方框、射线和红白骨骼，固定只显示 200 米内敌人。

## 使用

用 TrollStore 覆盖安装 `Core-17.0-21A327-TrollStore-v10-200m.ipa`。原“Core 环境准备”可以继续使用；完全关闭 Core 后先准备当前启动缓存，再打开 Core，按原流程初始化和获取信息。手机重启后需重新准备当前启动缓存。

位置页显示“200米标记”，唯一的“附近敌人”开关统一控制方框、射线、距离和骨骼，人类玩家与人机类别使用同一开关。旧类别开关、距离上限、粗细和颜色设置不改变本次显示策略。原同队筛选、无效距离过滤和屏幕投影检查保留；距离恰好 200 米纳入范围，超过 200 米不绘制。

方框、射线和距离为白色，方框、射线和骨骼固定为一个绘图单位宽的细线。骨骼沿用原 14 段关节点结构及原几何遮挡查询：线段两端都无阻挡时为白色，任一端有阻挡时为红色。这是关节点和线段层面的判断，无法在同一条骨骼中标出墙边的精确遮挡分界，也没有真实人物皮肤轮廓或模型填色。

打开标记开关会请求原遮挡数据准备，原就绪标志、原对象校验及原几何读取线程仍决定是否成功。原上下文、几何就绪状态或三项几何对象不可用时跳过红白骨骼，保留方框、射线和距离。没有把就绪状态强制设为成功，也没有修改原遮挡查询算法。刚开启时可能需要等待原几何数据准备。

## 修改范围

原自瞄和压枪输入函数从入口返回；渲染中的原自瞄候选计算也直接跳过。名称、血条、武器、雷达、物资、轨迹、预警、人数和辅助圈等显示保持关闭，旧配置无法重新开启这些绘制。初始化、缓存校验、数据读取和悬浮注册依赖保留。

按固定原 IPA 和主程序摘要核验后静态修改，90 个指令位置及三个等长标签属于允许范围。两个短分支辅助段复用同一渲染函数中已停用的候选计算指令，保留原渲染栈、PAC 和展开布局；无正常候选路径能落入辅助段。逐项变更包含在 `build-metadata.json` 的 `minimal_changes` 中，最终 IPA 的全部非签名载荷再次核对。未使用的原例程仍在二进制中，没有声称完整源码重写或物理删除所有其他代码。

本次保留既有授权组件处理，不改变服务器有效期或设备绑定，不上传本地卡密、崩溃日志或 kernelcache。没有新增反作弊隐藏、伪装或检测绕过功能，不能保证防封。此前 v8 的 7 天封禁原因仍未知；保留的游戏数据读取不因减少绘制而自动变得安全。

## 核验范围

28 项 Python 检查覆盖原输入身份、允许修改范围、缓存和内核代码保留、输入函数直接返回、菜单窗口配对和开关保存；新增 ARM64 指令执行检查覆盖旧配置隔离、200 米边界及 NaN/无穷距离拒绝、原方框与射线的端点和固定样式、实际 14 段骨骼循环、可见/遮挡/混合颜色以及原遮挡对象缺失时不绘制骨骼。另执行原查询函数，检查无命中及三种几何对象命中时的原返回值含义。原投影、几何和图形调用在测试中使用合成桩，未运行手机或游戏。

GitHub macOS 构建执行方法发布并发、真实 Mach 转发、缓存接收、子进程清理回归测试，以及两个 IPA 的签名、权限、依赖、资源和载荷核验。编译与包核验不能证明真实场景遮挡准确或规避游戏检测；v10 待设备验证。原后续 launchd 初始化超时仍未修复。
