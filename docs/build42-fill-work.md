- 4,935 次回调中，3,522 次填色关闭；1,413 次填色请求开启，其中 1,251 次几何未就绪，真正执行填色准备只有 **162 次**。141 次完成，21 次逐像素查询不完整，约为有效入口的 **13.0%**。
- 新增填色阶段累计 4.721 秒，按 162 个有效入口平均 **29.14 ms**，最大 **68.35 ms**。采集／模型读取平均 **11.73 ms**、栅格 **7.04 ms**、查询 **8.45 ms**、蒙皮 **0.82 ms**。这些阶段的平均值使用相同有效入口分母，不把 1,251 个几何未就绪回调混进去稀释。
- 关闭填色的原绘制平均约 **1.18 ms**、整个回调约 **1.19 ms**，与用户“明显减轻”相符。开／关组所处场景和就绪情况不同，不能用整个开启组平均值与关闭组计算性能倍率。
- 成功填色前，本地相机复制到提交平均 **14.68 ms**、最大 **24.32 ms**。该数字不包含相机缓存本身的年龄或之后实际屏幕呈现。
- 存在 59 次静态资源读取预算失败及 149 次布局拒绝。旧静态载入失败会丢弃已经读到的顶点／权重片段，下次再从头读取；每个目标单独 12 ms 的读取窗口也不能限制所有新资源在一帧中的累计工作。

## v14 改动

1. 静态顶点、权重、索引、分区骨骼表读取可以跨帧续接。成功读到的片段保存在最多 8 个任务、4 MiB 原始片段的 staging 缓存；匹配资源身份、完整静态描述及参考骨架后才复用。成功或实际读取／格式失败会释放片段，描述变化丢弃旧进度。布局错误等失败退避一秒。动态组件状态、变换、姿态、相机不进入跨帧缓存。
2. 每次填色回调的所有静态载入共享约 3 ms 的协作式工作额度，不能按目标反复重新获得额度。额度在后端读取之间检查；一次已进入的读取无法被强制抢占，因此不是总回调耗时的硬上限。动态姿态和已有模型继续使用原路径。
3. 较大遮罩且三角形较多时，CPU 栅格分为最多两组互不重叠的整行。每个像素保持原浮点公式及原三角形顺序；覆盖位图也按整行独占。只有纯 CPU 栅格并行，远程读取、几何查询和 ImGui 仍留在原线程。完成当前帧后再继续原逐像素红白查询，不使用上帧屏幕结果。
4. 保留 v13 的独立填色开关、停止自动详细采集、附近载具和 600 米范围。新增静态读取／复用字节、续接／退避次数、静态工作耗时及并行栅格帧数，供实机比较。

## 验证与边界

编译和自动化检查只在 GitHub Actions 执行。新增生产读取测试模拟每次后端调用耗时，验证跨两帧读取时顶点片段只读一遍、其他目标不能重置共享额度、描述变化会丢弃进度及 staging 内存边界。并行栅格测试将真实 libdispatch 输出与旧顺序逐像素对照，覆盖重叠、无效顶点、行边界、64 位字尾、非零原点及较大遮罩；分别使用 ASan/UBSan 和 ThreadSanitizer 检查。

本版本针对已证实的同步工作开销做优化，仍需手机报告确认收益；不能将云端通过当作已消除全部跟随延迟。逐像素查询的 12 ms 预算、实际 LOD、衣物形变／透明裁剪、源相机帧同步、最终显示提交和远距敌人漏显仍保留原限制。暂不盲目放大 9 分区服装布局上限或取消读取校验。
