Core 车辆适配采集 r6（保留 r5 分类试穿）
适用：iOS 17.0 / 21A327、巨魔、和平精英 1.38.12（15915）。

r2 已在你的手机上确认内核写入与回读成功。
r3 已由你确认能显示金龙外套并恢复白 T 恤。
r4 将操作整合进 Core 原悬浮菜单，用户已反馈安装包可用。
r5 增加分类与翻页：外套 60 项、头发 53 项、裤子 14 项、鞋子 5 项、降落伞 11 项。
共 143 个候选，名称和数字 ID 已与固定目录及包内 Item 表交叉核对。
仅金龙外套的实际画面已由用户确认，其余项目仍需逐项确认。
枪械、头盔、背包、大厅及包内自定义模型/材质/特效尚未接入。
r6 在“美化”的分类中加入“车辆适配”，独立采集当前乘坐车辆的外观数组和皮肤字段。
本版车辆是只读采集，尚未实现车辆换肤。不会把衣服的刷新开关套到车辆上。
使用游戏现有资源，未安装或替换 PAK 文件。

车辆采集方法：
1. 巨魔覆盖安装 Core-17.0-21A327-cosmetics-vehicle-r6.ipa，按原有流程初始化 Core 和游戏采集。
2. 进入训练场，坐进一辆轿车。保持在车内，不要切换座位或换车。
3. Core 原生菜单 →“位置”下面的“美化”→ 点“换分类”直到“车辆适配”→“采集车辆”。
4. 等待约 8 秒，标题显示“车辆报告已保存”。如果尚未上车，会等待最多约 60 秒。
5. 在“文件→我的 iPhone→Core”找到 Core-cosmetics-probe.json，将该报告发回。
   报告 mode 应为 vehicle-read-adaptation，主要内容是 latest_vehicle 和 samples。
   如显示 current-vehicle-unavailable，重新上车后再采集；如显示其他未确认状态，也请保留报告。
6. “停止采集”只停止车辆读取。采集期间选衣服项目，会先结束采集再开始试穿。
   如果仍有服装试穿进行中，先关闭试穿，再开始车辆采集。

原有服装试穿方法：
1. 巨魔覆盖安装 Core-17.0-21A327-cosmetics-vehicle-r6.ipa。
2. 穿戴需要试换部位的普通物品，进入训练场。
3. 返回 Core，等待原有初始化完成，并启动原有游戏采集。
4. 回到游戏，在 Core 悬浮菜单中点“位置”下面的“美化”。
   点“换分类”选择外套/头发/裤子/鞋子/降落伞，点“上一页/下一页”翻页。
   勾选一个项目开始 15 秒试穿；换选项目会先恢复上一项再试穿新项目。
5. 写入后约 15 秒自动恢复，也可关闭该开关提前恢复。
   系统结束后台运行时会提前尝试恢复。
6. 页面标题显示等待、试穿、恢复或失败状态。
   报告自动保存在“文件→我的 iPhone→Core→Core-cosmetics-probe.json”。
   报告仍是 Documents/Core-cosmetics-probe.json，重点是 apply、observations、restore。

如果显示“等待角色”，先完成初始化；准备阶段还没有写入。
若报告以 readiness-timeout 或 background-expiration 结束且没有 apply，初始化完成后再试。
如果是 matching-equipped-item-required，请先穿戴该部位的普通物品。
如果恢复报告显示会话/角色已变化，程序会停止写入以避免使用旧地址。
这些改动仅在当前游戏进程内，退出游戏并重新启动会恢复原始数据。

程序保留目标进程、会话代次、角色归属、数组布局、预期值及回读检查。
恢复只在仍属于本次试穿的数据上进行，游戏自行更改的服装不会被覆盖。
编译、自动化测试和签名验证全部由 GitHub Actions 执行。
报告会记录项目、分类、目标 ID 和原 ID；恢复保存的原外观，不会一律恢复白 T 恤。
报告还会只读采集手持武器的候选外观数组；这不代表枪械换肤已接入。
如要继续适配头盔、背包和枪械，请在训练场戴头盔、背包并手持枪后试穿一次，再发报告。
本版不是整包转换完成版，新增候选与分页菜单仍需手机确认。
车辆样本仅导出外观 ID、槽位、更新计数及原生方法的相对位置；不导出进程地址或物品实例 ID。
需要实机车辆报告后继续核对数据布局与刷新触发条件，不能仅凭包内配料表认定车皮已生效。
