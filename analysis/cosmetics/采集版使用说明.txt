Core 远程进程号核对 r15
适用：iOS 17.0 / 21A327、巨魔、和平精英 1.38.12（15915）。

r9 实机已确认：三字段写入成功，但 Pending 未被消费、游戏缓存计数没有推进，且你确认画面完全没变。
r10 增加只读的车辆外观实体、已加载物品、模型路径记录和刷新标记采集，供下一步定位。
本版是诊断包，车辆换肤尚未完成；菜单不再提供已经确认无效的 r9 宾利试换。

r11 在车辆适配页增加“探测游戏进程”。它只调用已有的内核进程名查找，名称固定为 ShadowTrackerExtra，不调用远程打开，不写车辆外观。
查找结果写进同一份 Core-cosmetics-probe.json：schema_version / probe_revision 为 11，mode 为 process-name-visibility。
lookup_result 为 located 表示这条查找看见了游戏进程；not-found 或 zero 表示没看见。报告不包含进程地址。
这不是车辆换肤包。r10 的实体采集仍然保留。

r15 修正 r14 写错的远程核对入口字节。按钮仍是“核对远程进程号”。它只在已经打开成功的会话上调用 Core 自己的 getpid 包装，不重新打开，不拆会话，不调用车辆函数，不改外观。隔离字已经是 1 时不会调用。
报告 schema_version / probe_revision 为 14，mode 为 remote-getpid-check。
pid_matches_published=true 只表示远程进程号等于已发布目标，不是换肤成功。
调度失败时 Core 自己可能把隔离字写成 3。入口或会话不满足时不会调用，菜单显示“远程会话未就绪”。

使用方法：
1. 巨魔覆盖安装 Core-17.0-21A327-cosmetics-vehicle-r15.ipa。安装会重启 Core。
2. 先让游戏留在前台。完全划掉 Core 后再打开它，立刻进入下一步。这一步不用上车。
3. 原生菜单“位置”下面“美化”→“换分类”到“车辆适配”。
4. 点一次“尝试打开游戏”。菜单显示“隔离状态挡住打开”就停，先导出报告，不要连点。
5. 打开调用返回后点一次“核对远程进程号”。
6. 立刻导出“文件 → 浏览 → 我的 iPhone → Core → Core-cosmetics-probe.json”。不要再点“探测游戏进程”，它会覆盖这份报告。

这次车辆采集如果 Core 当前目标不是 1.38.12 的游戏映像，会在第二次同样失败后停止，不再空转到约 60 秒。
latest_vehicle.status 会写成 image-pointer-unavailable、image-header-unreadable、image-header-not-macho、image-uuid-mismatch、image-uuid-unreadable 或 image-load-commands-unconfirmed。
这表示游戏绑定还没对上，不表示没上车。请先重新初始化 Core 的游戏采集，再使用“探测游戏进程”。

隔离字为 0 且进程名可见时，可点“尝试打开游戏”。它调用原入口 0x3A7D4，名称仍是 ShadowTrackerExtra，不修改车辆外观。
打开失败可能再次把隔离字写成 1。报告 mode 为 game-process-open-attempt，schema / probe 为 13。
open_result=returned-zero 且 target_pid_published=true 只表示远程打开返回了成功码并发布了目标，不是换肤成功。

历史车辆采集步骤，不是 r14 这一步要做的：
1. 安装包文件名以当次构建为准。
2. 按原流程初始化 Core 和游戏采集，坐进上次原车 ID 为 3349001 的四座敞篷车驾驶位。
3. 原生菜单“位置”下面“美化”→“换分类”到“车辆适配”→“采集车辆”。
4. 通常取得 8 个车辆样本后自动保存；未就绪时最多约 60 秒，也可手动停止。
5. 导出“文件 → 浏览 → 我的 iPhone → Core → Core-cosmetics-probe.json”。
   报告 schema_version / probe_revision 为 10，mode 为 vehicle-entity-resource-diagnostics。

报告新增 refresh_diagnostics：
- 实体映射、占用位和原生哈希查找是否一致。
- 实体类、Slot 0 和所属 Avatar 是否匹配。
- 当前 LoadedHandle 是否存在、类型能否确认、当前已加载物品 ID。
- 当前 MeshComponent、MeshAssetPath 和 LastUseMeshPath 是否有记录。
- RenderDirty / DelayRenderDirty 标记，以及原生缓存计数。
- 实体 vtable 和处理函数的相对位置。

资源判断边界：
这些信息只描述当前实体的加载记录，不扫描游戏磁盘资源，也不主动加载宾利。
target_resource_availability=not-checked 是明确的未检查状态，不能解释为资源已下载或未下载。
实体尚不存在或状态读取未确认时，报告会保留具体原因，不把它自动解释成“没有上车”。
本次车辆采集没有写入、远程函数调用、虚表修改或 PAK 替换。

原有 5 类服装的 143 个候选仍可单项试穿、约 15 秒恢复。
报告会覆盖同名旧文件，请先保存需要的旧报告。
报告不导出原始进程地址、PID、物品实例 ID、模型名称或磁盘路径。
所有编译、自动化回归、二进制分析和签名验证均在 GitHub Actions 执行。
