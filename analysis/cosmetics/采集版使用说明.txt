Core 车辆限时试换 r9（保留 r5 分类服装和 r8 取车路径）
适用：iOS 17.0 / 21A327、巨魔、和平精英 1.38.12（15915）。

r8 已由你的报告确认：8 次尝试均成功读取车辆 3349001，11 个同步槽位。
本版新增单车实验：4座敞篷跑车 3349001 → 宾利欧陆GT敞篷（火焰橘）3349002。
目前只开放这一组，必须匹配当前车辆、控制器、组件、实例和原同步数组。

本版提交原生 OnRep 中观察到的 PendingVehicleSkinID 数据请求，同时更新主槽 ID 和更新计数。
这条数据请求能否独立驱动画面尚未实机验证；不能把内存回读成功当作换肤画面成功。
没有远程调用游戏函数、改写虚表、修改角色 F50 刷新开关或替换 PAK。

车辆试换方法：
1. 巨魔覆盖安装 Core-17.0-21A327-cosmetics-vehicle-r9.ipa。
2. 按原流程初始化 Core 和游戏采集，在训练场坐进当前这辆“4座敞篷跑车”的驾驶位。
3. 原生菜单“位置”下面的“美化”→“换分类”到“车辆适配”。
4. 点“宾利试换15秒”。开始前约有 2 秒准备时间；试换期间保持在同一驾驶位。
5. 观察是否出现宾利外观，以及约 15 秒后是否恢复原车；也可以点“恢复原车”。
6. 导出“文件 → 我的 iPhone → Core → Core-cosmetics-probe.json”。
   报告 mode 应为 single-vehicle-request-trial，schema_version / trial_revision 应为 9。
   请将报告和“是否变车、是否恢复”的观察一起发回。

报告重点：
- apply.id_write_confirmed：主槽和更新计数写入是否确认。
- apply.pending_request_written：比较写接口是否确认提交原生待换肤请求。
- observations：主槽、更新计数、缓存计数、Pending、当前 / Real / Default ID。
- native_refresh_consumption_verified：是否观察到 Pending 归零且当前和 Real ID 都为目标。
- restore / restore_check / restore_observations：原数据和原车请求是否恢复，是否仍持有本次修改。
- visual_effect_verified 不会自动根据内存值变成 true，需要你的画面观察。

本版恢复会递增计数以标记恢复，不倒退原生更新计数。
如果请求未被消费且原车字段一直保持原值，会清理未消费的恢复请求并报告 memory-restored-refresh-unconfirmed。
如显示“等待恢复”或 change_still_owned=true，请保持同一车辆并点“恢复原车”，保留报告。
换车、角色 / 会话 / 实例或数组变更会停止旧地址写入；游戏自行改到其他值时不覆盖新值。
退出并重新启动游戏会重新建立这些进程内外观数据。

只读采集仍可用：车辆适配 → 采集车辆 → 取得 8 个样本或最多约 60 秒 → 导出同名报告。
采集报告 mode 为 vehicle-read-adaptation，schema_version / probe_revision 为 9。
采集和试换会覆盖同名报告，请先保存需要的那份。
采集普通车辆不需要账号拥有车皮，也不需要点游戏里的换肤按钮。

服装试穿仍有外套 60、头发 53、裤子 14、鞋子 5、降落伞 11，共 143 个候选。
选择分类并翻页，勾选一个项目试穿 15 秒，结束后恢复实际原物品。
金龙外套曾由你确认显示并恢复；其余候选没有逐项画面确认。
枪械、头盔、背包、大厅及包内自定义模型 / 材质 / 特效尚未接入。
存在未恢复的修改时会阻止开始另一项试换。

编译、自动化回归、二进制分析及签名验证全部在 GitHub Actions 执行。
报告不导出原始进程地址、PID 或物品实例 ID。
