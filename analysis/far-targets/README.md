# 原有远距目标漏显排查

2026-10-18，用户确认：有时 300～600 米内的敌人完全没有姓名、方框、射线或人物填色，进入约 300 米后才出现；不带填色的 v19 也有该现象。此反馈必须与填色查询超时／网格拒绝区分，不能继续只按填色问题解释。

## 已完成的核查

- 标记绘制的距离上限、骨骼采集门控及新增填色筛选均使用 600 米。已有云端 ARM64 合成回归覆盖 300.01、450、599.99、600 米，但输入是合成的有效目标记录，不证明实机已采集到全部远处目标。
- 只在 Actions 对固定原 Core 及当前最小显示补丁做只读分析：[39150862153](https://github.com/zwthys-cyber/Core-21A327-TrollStore/actions/runs/39150862153)。产物 `Core-far-target-acquisition-review` 包含原采集入口、绘制前筛选及上游候选的反汇编文本。
- `D7A88` 从上下文 `+0x3C0/+0x3C8` 的原始 24 字节记录列表进入，包含指针／队伍、字段读取、有效值等拒绝条件；`D8724` 才由当前位置计算米制距离。查看的距离分支未发现“目标距离大于 300 米即跳过”的直接常量比较。
- `D5A44..D5A60` 交换上游原始列表；显示用的缓存列表位于 `+0x3F0/+0x3F8`。需区分目标没有进入源列表、进入后读取／筛选失败、缓存里存在但标记未画出。
- 扩大扫描发现的 300 数值不能直接视为目标距离限制：例如 `C6128` 属于一个结构多字段有效性检查；`DB2DC`、`DB34C` 等还涉及其他界面／几何参数。没有证据支持仅凭常量改写。

## 未完成与结论边界

目前没有同一个远处目标靠近前后的原始列表／缓存快照。现有 `Core-model-render-status.json` 只有累计采集块数、填色阶段和失败计数，不含上述列表的逐目标阶段跟踪；它不能证明游戏未加载目标，也不能确认某个 300 米采集错误。

当前可确认的是 v19 已有的远距漏显现象，根因尚未确定。600 米是绘制／部分采集条件的上限，不应说成已保证 600 米内全部目标可获取。下一步若继续修复，需要在源列表与显示缓存之间增加有界的只读分阶段采样，并用靠近前后同一目标的实机证据定位；不得把未知目标数据强行视为有效或取消原校验来假装修复。

本分析分支不改变安装包或发布新版本。二进制分析均在 GitHub Actions 执行，本机仅阅读文本结果。
